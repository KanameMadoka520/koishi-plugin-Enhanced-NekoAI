# koishi-plugin-Enhanced-NekoAI

**基于 Qwen-VL（只是国内目前推荐的模型，你也可以改为任意你希望的模型） 的多模态拟人 AI 聊天插件**

这是一款高仿真度的 AI 群聊与私聊伴侣插件。内置专门针对 QQ 聊天习惯优化的文本排版逻辑、长短句拟人分段算法、本地表情包发送机制，以及强大的视觉多模态能力。本插件在原有基础上进行了大幅度的逻辑重构和功能追加，以适应现代大模型和复杂的群聊环境。

注：本项目由古早的 `neko-chatbot` 插件大幅度魔改而来。

### 2026年4月 图像节点 / Responses / xAI / OpenAI 图像增量更新

这一轮更新主要补齐了 **OpenAI Responses API、xAI Web Search、xAI 图像生成/编辑与 OpenAI gpt-image-2 参考图生图** 能力，并把“聊天模型节点”和“图像模型节点”彻底拆开，避免配置和路由互相污染。

#### 本轮重点

* **OpenAI Responses API 独立支持**：新增 `responses` / `openai-response` 节点类型，非流式兼容 `input_text`、`input_image` 与 `instructions`，适配更现代的 OpenAI / 兼容站 Responses 接口。
* **xAI Web Search（仅 Responses）**：在 `openai-response` 节点上新增可选的 xAI Web Search 开关，仅在开启时向 Responses 请求体附加 `tools: [{ type: "web_search" }]`，适合 xAI 官方 API + Grok 模型场景。
* **MiniMax Anthropic 兼容修复**：兼容 Anthropic 风格返回中 `thinking` 与 `text` 分块共存的情况，不再因只读 `content[0].text` 导致 `replace` 空指针异常。
* **独立图像节点池**：新增 `image_api_config.json`，图像生成 / 图像编辑节点独立于 `api_config.json` 管理。聊天节点继续只负责文本 / 多模态对话，图像节点只负责 `neko.生图` / `neko.修图`。
* **xAI / OpenAI 图像生成与参考图生图**：新增 `neko.生图`、`neko.画图`、`neko.修图`、`neko.图像模型列表`、`neko.图像模型搜索`、`neko.图像模型切换` 指令。OpenAI 图像节点默认模型为 `gpt-image-2`，在 `supportsEdit: true` 且配置 `editUrl` 时可接收引用图片。
* **图像输入输出链路优化**：修图命令会优先复用当前消息或引用消息中的图片，并尽量转成 `data:image/...;base64,...` 传给图像接口；`neko.生图` 在检测到当前图像节点支持编辑且消息里有图片时，会把图片作为参考图传入。输出优先读取 `b64_json`，必要时回退为 URL 下载后再转发给 QQ。
* **图像命令可选参数**：
  - `neko.生图`：支持 `--count` / `--ratio` / `--resolution` / `--model` / `--node`
  - `neko.修图`：支持 `--ratio` / `--resolution` / `--model` / `--node`
* **HTML 管理工具扩充**：除原有 `api_manager.html` / `config_editor.html` / `dashboard.html` / `history_viewer.html` 外，新增独立的 `image_api_manager.html`，专门管理 `image_api_config.json`。

### 2026年3月2日~3日 大版本更新内容（相对于上一版本）

本次更新是一次**从底层到顶层的全面重构**，将原先 1335 行的单文件架构彻底拆分为 15 个独立模块，并新增了大量核心功能。

#### 架构重构

| 项目 | 旧版 | 新版 |
|------|------|------|
| 代码架构 | 单文件 `index.js`（1335 行） | 15 个独立模块（`lib/` 目录） |
| 入口文件 | 所有逻辑混写在一起 | ~40 行薄壳，仅调用各模块初始化 |
| 全局状态 | 13 个散落的 `var` 变量 | 统一的 `state.js` 状态单例 |
| 日志系统 | 直接 `console.log` | 独立 `logger.js`，支持 debug/info/warn/error/critical 五级 |
| 配置管理 | 单层 key 合并 | 深层补丁合并（smartRouter、apiParams、memorySummary 等嵌套对象自动补齐新字段） |

#### 新增功能

* **智能路由与故障自愈** — 内置 API 节点路由引擎，支持 `failover`（按序故障转移）、`round-robin`（全局轮询）、`random`（随机选择）三种策略。主节点失败时自动尝试备选节点，最大重试次数和重试间隔均可配置。
* **长期记忆持久化** — 群聊和私聊的对话历史自动保存到本地 JSON 文件（`memory/group/`、`memory/private/`），插件重启后记忆不丢失。
* **记忆自动压缩** — 当对话条数超过阈值时，AI 自动总结旧消息为摘要，释放上下文窗口，保持长期记忆的连贯性。
* **用户黑名单系统** — 支持通过 `neko.黑名单添加/移除/列表` 指令动态管理，被拉黑用户的所有消息完全忽略。
* **按群独立人格绑定** — 不同群聊可绑定不同的人格预设（`neko.群人格绑定`），互不干扰。
* **按群独立模型绑定** — 不同群聊可绑定不同的 API 节点（`neko.群模型绑定`），一个群用 GPT、另一个群用 Claude，互不影响。
* **@专注回答模式** — 群聊被 @ 时，会把用户本轮发送的消息强制视为当前唯一主问题；历史上下文和被引用内容只作参考，除非用户明确要求总结，否则不会再擅自把长群聊整理成聊天记录总结。
* **回复引用上下文注入** — 用户在 @机器人 时引用了历史消息，插件自动提取被引用内容注入 AI 上下文。
* **@合并等待机制** — 用户连续多条 @消息会在时间窗口内合并为一次请求，避免重复触发浪费资源。
* **请求队列并发控制** — 内置 FIFO 队列，限制同时并发的 API 请求数量，防止高峰期雪崩。
* **队列状态提示与满队列拦截** — 收到请求时会在“处理中提示”里直接写出当前并发/排队状态；当并发已满时提示“NEKOAI请求并发已满，正在排队处理”，当排队长度达到上限时会直接拒绝新请求，并发送“NEKOAI请求队列已达上限”的提示消息。上述提示消息均会在 30 秒后自动撤回。
* **上下文闲置自动清空** — 支持在一段时间未收到新消息后自动清空上下文，降低旧上下文占比过高导致的新问题回答质量下降。
* **请求反馈可配置** — 收到请求后的“处理中提示”、失败时是否在聊天里回报错误、错误详情展示粒度、统一重试文案与 API 超时都已支持通过 JSON 配置。
* **优雅关闭** — 插件卸载或 Koishi 关闭时自动保存所有记忆数据，确保零丢失。
* **API 响应时间追踪** — 聊天日志新增 `responseTime` 字段，记录每次 API 调用耗时(ms)。
* **多主题图片卡片系统** — 在启用 `@seidko/koishi-plugin-puppeteer` 后，`neko`、`neko.群聊人格列表`、`neko.私聊人格列表`、`neko.状态面板`、`neko.当前群状态` 会优先以图片卡片输出；`neko.模型列表` 也可通过指令开启高密度分页图片渲染。支持 `neko.UI 1/2/3` 在三套主题（极光玻璃 / 深色终端 / 暖纸卡片）间切换，当渲染失败或服务不可用时自动回退为文本，不影响命令可用性。

#### 增强改进

* **拟人分段算法增强** — 当句子包含列表项（`•`）、标题框（`【`）或数字序号时，合并吸附概率飙升至 98%，防止把结构化内容拆成碎片轰炸群聊。
* **配置热重载增强** — 新增字段自动合并到现有配置，嵌套对象（smartRouter、apiParams 等）支持字段级补丁，旧配置文件无需手动添加新字段。
* **引用消息兼容增强** — 针对 Koishi + OneBot 6.x / Satori 链路补强了回复检测：会优先读取 `session.quote`，并兼容 `reply/source`、`<quote .../>`、`[CQ:reply,...]` 等多种结构；被回复消息里的文字和图片都会尽量一起送给模型。
* **闲置清空计时器优化** — 自动清空上下文的计时器现在只会在收到新上下文时启动或重置；插件启动、重载配置或长期闲置期间，不再无意义地持续刷“已重置自动清空计时器”的日志。
* **`<think>` 标签过滤** — 自动剥离 Claude 等模型输出的推理过程标签，只保留最终回复。
* **循环依赖解决** — 模块间需要互相引用时使用延迟 `require()`，彻底消除加载顺序问题。

### 核心特性

* **强大的视觉多模态能力 (Visual Multi-modal)**：
* 支持无缝识别群聊和私聊中的图片。采用 Base64 传输，内置 6MB 体积自动拦截防报错机制，超过限制的图片会被安全忽略。
* **外部链接提取支持**：除了原生协议图片，插件还会自动从纯文本中嗅探并提取 `http/https` 结尾的图片链接（如 jpg/png/webp 等），转化为视觉输入。
* **非视觉模型容错保护**：如果配置了纯文本大模型却接收到了图片，插件在捕获到底层 API 的 Bad Request 报错时，会进行智能拦截，向用户优雅地抛出提示（“无法处理此图片...”），并记录详细日志，防止节点崩溃。


* **上下文精准阅读与总结 (Context Sniffing)**：
* 强大的历史记录嗅探功能。可以直接让 AI 读取当前环境的最近消息，建立丰富的短期记忆。
* **精准过滤提取**：支持精确提取并总结某个特定群友的发贴记录，有效排除群内其他人的插话干扰，让 AI 做到“只看 ta 说的话并进行分析总结”。


* **完美指令避让与运行提示 (Command Avoidance & Logging)**：
* 内置全局指令清洗与黑名单拦截逻辑。当用户触发 Koishi 其他插件的指令（如 help 等）时，AI 会完美保持沉默，不会发生“抢答报错”的尴尬情况。（该黑名单字典填写在 `commands.json` 里，支持前缀匹配与全词匹配，请根据需要自行添加）。
* **全局链路透明化**：新增了极其详细的控制台日志反馈。无论是触发全局避让、@避让，还是 AI 识别到对话并准备调用 API 请求数据时，都会在控制台输出包含 **[节点名称]、[接口格式]、[包含图片数]、[上下文长度]** 等核心指标的提示信息，方便服主直观确认机器人的底层运行状态与耗时。


* **高拟人分段与极限排版清洗 (Human-like Formatting)**：
* **长短句拟人打散算法**：AI 不再像机器一样一次性吐出几千字。插件会根据标点符号（如句号、问号、叹号）对大模型的输出进行切片，并基于动态概率决定是合并短句还是分开发送，模拟真人“敲回车”的连发习惯。
* **QQ 专属 Markdown 清洗**：自动剥离大模型输出的冗余 Markdown 格式。将代码块（```）转换为普通换行，去除加粗（**）、斜体（*），并将大标题（#）转换为更加原生的【括号标签】，彻底适配移动端群聊的阅读体验。
* **强排版吸附与防碎嘴（New）**：针对上述的打散算法进行了针对性增强。当句子中包含列表项（`•`）、标题框（`【`）或数字序号（如 `1.`、`2.`）时，合并吸附概率会临时飙升至 98% 以上。这确保了 AI 在输出教程、长篇条目或代码解析时，能完美保留原始的换行与缩进结构，拒绝把一个列表拆分成十几条消息轰炸群聊（防碎嘴）。


* **🔥 智能合并转发防刷屏与 Fallback 降级机制**：
* 针对深度问答或大篇幅输出，新增基于 Satori 协议的原生合并转发（消息卡片）机制，并提供由双重阈值驱动的智能判断。
* **三重策略控制 (`forwardStrategy`)**：支持 `auto`（智能自动判断）、`on`（强制全文开启合并）、`off`（强制关闭合并，一律打散发送）三种指令级热切换策略。在 `auto` 模式下，当单次回复的总字数（如超过 300 字）或被拟人算法切分的分段数（如超过 5 段）只要有一个触达设定阈值，AI 就会自动将这些碎片文本打包成一条整洁的合并转发消息发出，彻底告别长文刷屏烦恼。
* **无缝 Fallback 降级防吞锁**：众所周知，QQ / Satori 协议的“合并转发”接口有着极其严苛的风控限制。如果长文本包含特定敏感词，或协议端（如 OneBot / NapCat）数据结构校验失败，底层接口会直接报错（如 retcode: 1200）。为此，本插件设计了强大的底层自救拦截器：**当尝试进行合并转发遭遇抛错时，程序绝对不会崩溃，也不会导致 AI 费尽心思生成的几千字长文“石沉大海”。** 插件会立即 Catch 异常，在控制台打印 `⚠️ 触发 Fallback：已被拦截，自动降级退回普通逐段发送机制...` 的警告，并**瞬间无缝切换为普通的逐条文本分段发送模式**，强行把回复塞进群聊，保证服务高可用！


* **群聊动态限流控制（Group Rate Limits）**：
* 新增基于 12 小时周期（以东八区早 6 点至晚 6 点为天然潮汐界限）的群聊调用次数限制。支持为不同的群聊单独设置响应上限。
* **智能阶梯预警**：调用次数达到上限的 50% 和 80% 时，AI 会自动在群内发送额度告警；额度耗尽后执行硬拦截，拒绝响应非主人的提问。主人（Master）永远拥有最高特权，可通过 `@` 机器人无视限流强行调用。
* **数据安全隔离**：额度配置（`runtime_config.json`）与实时计数器（`group_usage_counts.json`）物理分离，彻底保障配置文件的纯净，避免高频 I/O 读写导致配置文件损坏。


* **精细化聊天日志溯源（Detailed Chat Logs）**：
* 自动在本地根目录生成 `chat-history` 文件夹，按 `YYYY-MM-DD_Day/Night` 周期滚动生成结构化的 JSON 对话日志。
* **高维数据留痕**：详尽记录单次对话的群号、触发者真实昵称、用户 Prompt、AI 完整回复文本、附带的上下文长度（Token估算参考）、当前所调用的 API 节点名称及备注。
* **审计与瘦身优化**：自动剥离极其冗长的 Base64 图片编码以大幅度节省磁盘空间；在 API 请求失败或触发风控时，日志的 `isError` 状态会标记为 true，并将报错原因（Error Message）写入回复内容中，方便服主随时进行安全审查与故障溯源。


* **动态表情包系统（Dynamic Memes）**：
* 根据语境（Prompt 设定强制输出的情绪标签）自动触发各类情绪，并从本地对应的分类文件夹中随机抽取发送表情包图片，为拟人化注入灵魂。


* **全量 JSON 本地配置（No More YAML）**：
* 彻底脱离繁杂且易错的 `koishi.yml`！所有核心配置参数、API 节点管理、防风控阈值均采用插件目录下的独立 JSON 文件管理，且完全支持通过聊天环境使用指令（`neko.重载配置`）一键热重载，即改即用。


* **多模型与多人格无缝切换（Native Multi-Protocol & Personas）**：
* **多节点池**：支持随时在群聊中通过指令动态添加、查看、切换 API 节点（中转站 / 备用模型），无需触碰服务器后台。
* **原生底层请求适配**：内置原生支持 **OpenAI Chat Completions、OpenAI Responses API、Anthropic (Claude) 以及 Gemini** 四类文本/多模态接口请求格式。插件会在发包前，根据你配置的格式标签（`aiType`），在底层动态重组请求体（如 Responses 的 `instructions + input`、Anthropic 的 `messages` 结构与 `max_tokens` 强校验，或 Gemini 的 `contents` 与 `parts` 嵌套格式）。彻底拒绝因中转站格式转换不佳导致的兼容性报错。
* **xAI Web Search（Responses 专属）**：当节点类型为 `openai-response` 且显式开启 xAI Web Search 时，插件会为请求附加 `tools: [{ type: "web_search" }]`。该能力默认关闭，只建议在 xAI 官方 API + Grok 模型场景下使用。
* **独立图像节点池**：图像生成 / 图像编辑已从聊天节点中拆出，使用单独的 `image_api_config.json` 管理，不再混入 `api_config.json`，避免聊天路由与图像路由互相影响。
* **xAI / OpenAI 图像生成与参考图生图**：支持 `POST /v1/images/generations`，支持编辑能力的节点还会通过 `POST /v1/images/edits` 处理修图或参考图输入。OpenAI 图像节点默认模型为 `gpt-image-2`，配置 `supportsEdit: true` 与 `editUrl` 后可接收引用图片。图像命令优先使用 `image_api_config.json` 中的活跃图像节点，而不是聊天节点。
* **独立双轨人格**：支持分别为群聊和私聊建立独立的 Prompt 人格库，并在对话中一键无缝热切换。


* **严格的主人权限控制（Master Authorization）**：
* 所有敏感调参、系统设定修改、节点查询及人格切换指令均被严格锁定系统。非 `masterQQ` 列表中的用户一旦触碰会立刻拦截并提示权限不足，保障机器人资产与设定的绝对安全。


* **智能路由与故障自愈（Smart Router）**：
* 内置 API 节点智能路由引擎，支持 `failover`（按序故障转移）、`round-robin`（全局轮询）和 `random`（随机选择）三种策略模式。当主节点请求失败时，自动尝试备选节点，最大重试次数和重试间隔均可配置，确保 AI 服务高可用。
* 支持排除指定节点编号，灵活管理节点池。

* **长期记忆持久化与自动压缩（Long-term Memory）**：
* 群聊和私聊的对话历史自动持久化保存到本地 JSON 文件（`memory/` 目录），插件重启后记忆不丢失。
* 内置自动记忆压缩机制：当对话条数超过配置阈值时，AI 自动总结旧消息为摘要，释放上下文窗口，保持长期记忆的连贯性。

* **用户黑名单系统（User Blacklist）**：
* 支持通过指令动态管理用户黑名单，被加入黑名单的用户的所有消息将被完全忽略，包括群聊 @提及和私聊。

* **按群独立人格/模型绑定（Per-Group Binding）**：
* 支持为不同群聊绑定不同的人格预设和 API 模型节点。每个群可以有独立的 AI 性格和使用不同的模型，互不干扰。未绑定的群使用全局默认配置。

* **回复引用上下文注入（Quote Extraction）**：
* 当用户在 @机器人 时引用了一条历史消息，插件会自动提取被引用消息的发送者、文本和图片，并优先注入到本轮提问上下文中；对 OneBot 6.x / Satori 下常见的 `session.quote`、`reply/source` 和 CQ reply 标记都做了兼容。

* **@专注回答模式（Mention Focus Mode）**：
* 当群友直接 @机器人 时，系统会把本轮 @ 消息视为唯一主问题。除非用户明确要求“总结/回顾/整理聊天记录”，否则模型不会再把长上下文误判成总结任务。

* **@合并等待机制（Mention Merge Wait）**：
* 当用户连续发送多条消息 @机器人时，插件会等待配置的时间窗口，将多条消息合并为一次请求，避免重复触发和资源浪费。

* **请求队列并发控制（Request Queue）**：
* 内置请求队列系统，限制同时并发的 API 请求数量，防止高峰期 API 雪崩。

* **优雅关闭与数据保护（Graceful Shutdown）**：
* 插件卸载或 Koishi 关闭时，自动保存所有群聊和私聊的记忆数据，确保数据零丢失。

* **模块化架构（Modular Architecture）**：
* 代码从单文件 1360 行重构为 15 个独立模块（`lib/` 目录），每个模块职责单一、依赖清晰，极大提升了可维护性和可扩展性。

```yaml
plugins:
  # ... 其他插件 ...
  ./plugins/koishi-plugin-Enhanced-NekoAI: {} # 插件已全量迁移至 JSON，此处留空即可


```

#### 本地数据文件与目录说明

首次启动插件后，插件会在其同级目录下自动生成以下 JSON 配置文件与目录：

1. **`runtime_config.json` (核心运行配置)**

* **`masterQQ`**: 你的主人 QQ 号列表（如 `["123456789"]`）。**必须首先修改此项**，否则你将无权使用任何高级管理指令。
* **`groups`**: 允许 AI 监听、记录和回复的群号列表（如 `["111111111", "222222222"]`）。
* **`groupLimits`**: 记录各个群聊的 12 小时响应次数上限（如 `{"111111111": 100}`）。
* **`contextAutoForgetMs`**: 上下文闲置自动清空时间（毫秒），`0` 为关闭。默认 10 分钟。
* **`groupMentionFocusMode`**: 群聊 @ 专注回答模式，默认 `true`。开启后，被 @ 时优先围绕本轮消息回答，上下文与引用仅作参考；如需恢复旧行为，可关闭该字段。
* **`apiTimeoutMs`**: 调用下游聊天模型的超时时间（毫秒）。
* **`imageApiTimeoutMs`**: 调用下游图像接口的超时时间（毫秒），只影响 `neko.生图` / `neko.修图`。默认 `300000`，也就是 5 分钟。
* **`sendProcessingNotice` / `processingNoticeText` / `processingNoticeDelayMs`**: 控制收到请求后是否先发“处理中”提示、提示文案以及延迟多久再发。提示消息会在发送后 30 秒自动撤回（需平台支持删除消息），如需关闭可将 `sendProcessingNotice` 设为 `false`。
* **`requestQueue.maxConcurrent`**: 请求队列允许同时进行的 API 请求数量。默认 `3`。
* **`requestQueue.maxPending`**: 允许等待中的请求数量上限，`0` 表示不限制。默认 `10`。达到上限后会直接拒绝新的请求。
* **`requestQueue.overflowText`**: 队列已满时发送给用户的提示文案。支持占位符 `{ahead}` `{running}` `{pending}` `{maxConcurrent}` `{maxPending}`。
* **`sendFailureNotice` / `failureNoticeDetailMode` / `generationFailedText`**: 控制失败时是否在聊天里回报错误、要不要带节点与错误详情，以及统一的失败重试文案。
* **`forwardStrategy`**: 消息合并策略开关，可选 `auto`（触发阈值则合并）、`on`（强制合并）、`off`（禁用合并）。
* **`uiStyle`**: 图片卡片主题编号。`1` = 极光玻璃，`2` = 深色终端，`3` = 暖纸卡片。
* **`modelListImageEnabled`**: 是否启用模型列表的图片分页渲染。默认关闭，适合节点很多时按页查看。
* **计时器行为说明**: `contextAutoForgetMs` 对应的自动清空计时器只会在收到新的群聊/私聊上下文后才启动或重置，闲置期间不会持续计数刷日志。
* **队列提示行为说明**: 若 `sendProcessingNotice` 开启，则收到请求时的提示消息会自动写入当前并发/排队情况；当并发已满时会显示“正在排队处理”，当 `requestQueue.maxPending` 达到上限时会显示“请求队列已达上限，请稍后重试”，并统一在 30 秒后自动撤回。
* 该文件内自带 `_comments` 字段，以中文详细解释了包括插嘴概率、打字延迟时间、合并转发字数/段数等所有微调参数的作用。

2. **`runtime_schema.json` (运行时配置契约)**

* 用于声明当前版本插件真实支持的配置字段、章节、字段说明、枚举值、范围约束以及废弃字段/旧值迁移信息。
* 配套 GUI Manager 会读取它来显示字段说明、导入校验、迁移提醒和自检提示。

3. **`api_config.json` (多节点 API 配置)**

* 在此文件内可无限添加不同的聊天 API 站点和模型。包含 `apiUrl`, `modelName`, `apiKey`, `remark` (备注)。
* **核心字段 `aiType`**：可选值为 `openai`、`responses`、`anthropic` 或 `gemini`。GUI 中会把它们显示为 `openai (completions)`、`openai-response`、`Anthropic`、`Gemini`；其中 `openai-response` 本质上仍会归一化为 `responses` 处理。
* **`xaiWebSearchEnabled`**：仅对 `responses` / `openai-response` 节点生效。开启后会为 Responses 请求附加 xAI Web Search 工具；默认关闭，建议仅在 xAI 官方 API + Grok 模型场景使用。

4. **`image_api_config.json` (独立图像 API 配置)**

* 专门给 `neko.生图` / `neko.修图` / `neko.图像模型列表` / `neko.图像模型搜索` / `neko.图像模型切换` 使用。
* 每个节点包含 `providerType`, `generationUrl`, `editUrl`, `apiKey`, `modelName`, `remark`, `aspectRatio`, `resolution`, `supportsEdit`。
* 当前内置 `xai` 与 `openai` 两类图像 provider；xAI 默认 `supportsEdit: true`，OpenAI `gpt-image-2` 默认 `supportsEdit: true`。如需让某个节点只做文生图，可以显式设置 `supportsEdit: false`。

5. **`group_personality.json` & `private_personality.json` (独立人格库)**

* 分别管理群聊和私聊的 Prompt（系统提示词/世界观设定），支持在群内发送指令进行轮盘式一键切换。

6. **`group_usage_counts.json` (群聊限流计数器)**

* 独立存储当前周期的群聊调用计数。跨越早晚 6 点分界线时，会自动重置当前周期 `periodId` 并将计数清零。

7. **`chat-history/` (历史对话日志目录)**

* 自动生成的本地行为审计文件夹，按 `YYYY-MM-DD_Day/Night.json` 格式滚动持久化保存脱敏后的轻量级对话日志。

8. **`memory/` (长期记忆持久化目录)**

* 自动存储群聊和私聊的对话记忆 JSON 文件，插件重启后记忆自动恢复。记忆压缩后的摘要也保存在此目录中。

9. **`commands.json` (指令避让字典)**

* 定义需要避让的 Koishi 指令前缀列表，防止 AI 抢答其他插件的指令。

10. **`lib/` (模块化源码目录)**

* 插件核心逻辑按功能拆分为 15 个独立模块：`state.js`（全局状态）、`logger.js`（分级日志）、`config.js`（配置管理）、`utils.js`（工具函数）、`parser.js`（消息解析）、`sender.js`（消息发送）、`api.js`（API 调用）、`queue.js`（请求队列）、`ratelimit.js`（群聊限流）、`history.js`（历史日志）、`memory.js`（长期记忆）、`memes.js`（表情包）、`commands.js`（指令注册）、`listener.js`（事件处理）、`render.js`（帮助菜单 / 人格列表 / 模型列表 / 状态面板图片卡片渲染）。

修改完核心 JSON 文件后，无需重启 Koishi，直接向机器人发送 **`neko.重载配置`** 指令即可瞬间生效！

### 指令列表与用法

#### 动态调参指令（⚠️ 仅限主人可用）

这些指令可以直接在聊天窗口发送，配置会立即生效并保存在本地 `runtime_config.json` 中，重启或断电绝不丢失：

* `neko.重载配置`：从本地文件重新加载运行时的所有 JSON 设置（核心配置、API、人格），手动修改 JSON 文件后必备指令！
* `neko.合并消息 [开/关/自动]`：**强制干预智能合并转发策略**。当发现底层协议持续崩溃退回逐段发送（Fallback）时，可以直接发送 `neko.合并消息 关` 临时切断合并引擎，或使用 `自动` 恢复基于阈值的智能判断。
* `neko.表情包概率 <数字0-1>`：控制 AI 回复时附带本地情绪表情包的概率。（示例：`neko.表情包概率 0.5`，即 50% 概率带图）
* `neko.随机回复概率 <数字0-1>`：控制群聊开启话痨潜水模式时，满足一定消息量后，AI 突然插嘴回复的概率。（示例：`neko.随机回复概率 0.3`）
* `neko.随机回复检测数 <整数>`：控制群聊每累计滚动多少条群友消息，才进行一次插嘴概率的掷骰子判定。（示例：`neko.随机回复检测数 15`）
* `neko.合并字数阈值 <整数>`：设置 AI 自动合并机制的总字数触达底线。（示例：`neko.合并字数阈值 300`）
* `neko.合并段数阈值 <整数>`：设置 AI 被拟人算法切分为多少个气泡分段以上时，强制收束为合并转发卡片。（示例：`neko.合并段数阈值 5`）
* `neko.UI [1/2/3]`：切换帮助菜单、人格列表、模型列表图片页、状态面板所使用的图片主题风格。

#### 限流与状态管理指令（⚠️ 仅限主人可用）

* `neko.状态面板`：查看当前生效模型、群聊人格、私聊人格、UI 风格、智能路由、队列状态、黑名单人数、群绑定数量等总览信息；若在群聊内调用，还会自动补充“当前群上下文”一栏。
* `neko.当前群状态`：查看当前所在群的监听状态、独立人格绑定、独立模型绑定、当前限流周期、已用次数与剩余额度，适合在具体群里快速排障。
* `neko.群绑定列表`：查看所有**已配置独立人格绑定或独立模型绑定**的群聊总览。该命令默认不列出所有监听群，只展示真正做过绑定的群，避免暴露过多敏感信息。
* `neko.群聊限制 <群号> <次数>`：设置指定群聊单周期（12 小时内）的 AI 响应次数天花板。（输入 0 或负数可彻底取消该群的限制）。
* `neko.群聊限制查询`：查询当前 12 小时周期内，本群聊已经耗费的对话额度与限制状态。

#### 多节点 API 管理指令（⚠️ 仅限主人可用）

* `neko.模型添加 <apiUrl> <apiKey> <模型名称> [备注]`：动态添加一个新的 API 节点配置（**默认构建结构为 OpenAI 兼容格式**）。
* `neko.Anthropic格式模型添加 <apiUrl> <apiKey> <模型名称> [备注]`：动态添加一个 **Anthropic (Claude)** 原生 Payload 格式的 API 节点，自动适配 `messages` 块与必要的请求头参数。
* `neko.Gemini格式模型添加 <apiUrl> <apiKey> <模型名称> [备注]`：动态添加一个 **Gemini** 原生 Payload 格式的 API 节点，自动适配 `contents` 树与大文本参数映射。
* `neko.模型列表 [页码]`：查看所有已保存的 API 节点列表及分配的编号。默认仍可使用纯文本 / 合并转发逻辑；若开启图片模式，则按页查看。
* `neko.模型搜索 <关键词> [页码]`：按 `modelName` 检索节点，不区分大小写。适合在 100+ 节点池里快速找出所有包含 `grok`、`claude`、`gemini` 等关键词的模型。
* `neko.模型列表图片 [开/关]`：开关模型列表图片分页渲染。开启后通过 `neko.模型列表 1`、`neko.模型列表 2` 等方式分页查看；默认每页 30 个节点、5 列排布，适合 100+ 节点规模。
* `neko.模型列表输出合并 [enable:string]`：开关文本模式下的合并转发输出。**仅在模型列表图片渲染关闭时生效。**
* `neko.模型切换 <编号>`：一秒无缝切换当前发包的底层 API 节点与模型，对话过程中随时可用。

补充说明：

* `openai-response` / Responses 节点当前更推荐通过 GUI Manager、`api_config.json` 或插件内 `api_manager.html` 直接维护；这样也更方便同时配置 `xaiWebSearchEnabled`。
* URL 仍然建议你自己掌控完整路径。GUI / HTML 管理器里的“补默认后缀”按钮只是辅助，不会强行改写你的兼容站后缀。

#### 图像节点与生图指令（⚠️ 仅限主人可用）

* `neko.图像模型列表 [页码]`：查看 `image_api_config.json` 里的独立图像节点列表。
* `neko.图像模型搜索 <关键词> [页码]`：按备注 / 模型名 / 生成 URL / 修图 URL 搜索图像节点。
* `neko.图像模型切换 <编号>`：切换当前默认图像节点，对应 `runtime_config.json` 的 `activeImageApiIndex`。
* `neko.生图 <提示词>`：调用图像生成节点。支持 `--count`、`--ratio`、`--resolution`、`--model`、`--node`；当当前节点支持编辑且当前/引用消息带图时，会把图片作为参考图一起传入。
* `neko.画图 <提示词>`：`neko.生图` 的别名。
* `neko.修图 <提示词>`：调用图像编辑节点。会优先复用当前消息或引用消息里的图片，支持 `--ratio`、`--resolution`、`--model`、`--node`。

常见示例：

* `neko.图像模型搜索 grok`
* `neko.生图 赛博朋克夜雨中的猫娘 --count 2 --ratio 16:9 --resolution 2k`
* 引用一条带图消息后发送：`neko.生图 按这张图的角色画成水彩插画`
* `neko.修图 给她加一顶黑色贝雷帽 --ratio 1:1`

补充说明：

* 图像节点和聊天节点完全分离。`neko.模型列表` 不会显示生图/修图节点，图像相关请使用 `neko.图像模型列表`。
* 当前内置的图像 provider 包括 `xai` 与 `openai`，两者都推荐使用 `generationUrl = /v1/images/generations`；支持编辑的节点还应配置 `editUrl = /v1/images/edits`。OpenAI `gpt-image-2` 节点可在 `supportsEdit: true` 时处理引用图，用户可直接引用带图消息后发送 `neko.生图 提示词` 做参考图生图。
* 输出链路会优先读取 `b64_json` 直接回传到 QQ；如果下游只返回 URL，插件会自动下载后再发送；如果 OpenAI Compatible 返回 Markdown 形式的 data URI 图片，也会自动提取发送。

#### 独立人格管理指令（⚠️ 仅限主人可用）

* `neko.群聊人格添加 <备注> <提示词>` / `neko.私聊人格添加 <备注> <提示词>`：录入全新的 Prompt 世界观系统提示词。
* `neko.群聊人格列表` / `neko.私聊人格列表`：查看所有人格预设，并显示带有 `(当前使用) 👈` 标记的生效人格。若启用了 `@seidko/koishi-plugin-puppeteer`，会优先以双列图片卡片形式展示。
* `neko.群聊人格切换 <编号>` / `neko.私聊人格切换 <编号>`：一键切换对应场景下的大脑思维人设。

#### 上下文阅读与总结指令（所有人可用）

* `neko.阅读 [数量]`
* 说明：打破原有的逐级渐进记忆，命令 AI 瞬间重新拉取当前群聊或私聊最近的指定条数消息，强制灌入短期记忆池。
* 用法：`neko.阅读 20`
* `neko.读取记录 @某群友 [数量]`
* 说明：让 AI 穿越群聊消息的海洋，定向过滤、精准提取并强行记住该被 `@` 群友最近的专属发言记录。
* 用法：`neko.读取记录 @小明 50`
* `neko.总结记录 @某群友 [数量]`
* 说明：调用大模型推理能力，抓取指定群友近期的多条发言碎片，并立刻针对该用户近期的话题、情绪、关注点输出一份“太长不看”版的精准总结报告。
* 用法：`neko.总结记录 @张三 30`

#### 基础管理指令（⚠️ 大部分仅限主人可用）

* `neko.forget`：给 AI 执行”记忆消除术”，立刻清空当前环境下的短期上下文数组并清除持久化记忆文件，可用于快速纠正 AI 话题跑偏。
* `neko.reloadcmd`：热重载本地的 `commands.json` 避让指令字典文件，无需重启整个 Koishi 框架。
* `neko.onlymaster`：全局安保模式：切换至仅主人私聊响应（无情拒绝非白名单的任何陌生人私聊轰炸）。
* `neko.onlyfriends`：群友优待模式：切换至仅允许 AI 所在群的群友（需要数据文件缓存支持）发起私聊。
* `neko.LM`：开发调试利器：以纯字符串形式打印当前会话底层的上下文记忆 JSON 堆栈。

#### 黑名单管理指令（⚠️ 仅限主人可用）

* `neko.黑名单添加 <QQ号>`：将指定用户加入黑名单，该用户的所有消息将被完全忽略。
* `neko.黑名单移除 <QQ号>`：将指定用户从黑名单中移除，恢复正常响应。
* `neko.黑名单列表`：查看当前黑名单中的所有用户。

#### 按群独立绑定指令（⚠️ 仅限主人可用）

* `neko.群人格绑定 <群号> <人格编号>`：为指定群聊绑定独立的人格预设。输入编号 `-1` 可取消绑定，恢复使用全局默认人格。
* `neko.群模型绑定 <群号> <API编号>`：为指定群聊绑定独立的 API 模型节点。输入编号 `-1` 可取消绑定。
* `neko.群绑定列表`：主人专用总览命令。分开展示“人格绑定”与“模型绑定”两块，只列出真正已经设置绑定的群，便于统一排查和管理。

#### 智能路由管理指令（⚠️ 仅限主人可用）

* `neko.智能路由 [开/关]`：开启或关闭智能路由引擎。开启后，API 请求失败时自动尝试备选节点。
* `neko.路由模式 [failover/round-robin/random]`：切换路由策略模式。
* `neko.日志级别 [debug/info/warn/error]`：动态调整日志输出级别，无需重启。

#### 帮助指令（所有人可用）

* `neko`：显示精简版指令帮助菜单，列出所有可用指令分类。若启用了 `@seidko/koishi-plugin-puppeteer`，会优先输出双栏图片卡片。
